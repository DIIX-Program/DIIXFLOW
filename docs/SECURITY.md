# FlowOps Security Architecture & Threat Model

## 1. Zero Trust Principles & Overview

FlowOps implements a **Defense-in-Depth** security architecture:
1. **Never trust client input**: All parameters, IDs, and payloads undergo schema validation (Zod) on both frontend and backend.
2. **Never trust client tenant claims**: Workspace membership is validated against verified Cognito JWT claims and DynamoDB membership records on every request.
3. **No arbitrary code execution**: Workflow actions execute predefined, sandboxed AWS Lambda task runners. Users cannot execute arbitrary raw JavaScript or Python in the host process.
4. **Task Token Isolation**: AWS Step Functions task tokens are stored exclusively on the server side and never sent to frontend clients.

---

## 2. Authentication & Authorization (RBAC)

### 2.1 Identity Management
- **Provider**: Amazon Cognito User Pools with SRP (Secure Remote Password) protocol.
- **Tokens**: Short-lived Access Tokens (1 hour), Refresh Tokens (30 days), and ID Tokens carrying tenant claims.
- **Multi-Factor Authentication (MFA)**: Enforced for administrative operations.

### 2.2 Role-Based Access Control Matrix

| Role | View Dashboards & History | Create / Edit Workflows | Publish & Deploy to AWS | Trigger Executions | Approve Tasks | Manage Connections & Secrets |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| **ADMIN** | Yes | Yes | Yes | Yes | Yes | Yes |
| **BUILDER** | Yes | Yes | Yes | Yes | No | Yes (Read/Create) |
| **OPERATOR**| Yes | No | No | Yes | Yes | No |
| **VIEWER** | Yes | No | No | No | No | No |

## 3. Network & SSRF Protection

### 3.1 HTTP Request Node SSRF Defense
Because the `actionHttp` node allows workflows to make outbound requests to external APIs, strict Server-Side Request Forgery (SSRF) protections are enforced at the Lambda executor level:
- **IP Denylist**: Resolves target DNS hostnames before socket connection and blocks:
  - `169.254.169.254` (AWS Instance Metadata Service)
  - `127.0.0.0/8` (Loopback)
  - `10.0.0.0/8` (Private Class A)
  - `172.16.0.0/12` (Private Class B)
  - `192.168.0.0/16` (Private Class C)
  - `::1` and IPv6 link-local addresses
- **Protocol Whitelist**: Only `https://` and `http://` schemes are permitted (`file://`, `gopher://`, `ftp://` are rejected).

---

## 4. Webhook Security & Ingestion

### 4.1 Inbound Webhook Verification
- **HMAC Signatures**: Supports SHA-256 HMAC signature verification (`X-FlowOps-Signature`).
- **Timestamp Validation**: Rejects requests where the timestamp is older than 300 seconds (5 minutes) to prevent replay attacks.
- **Idempotency Keys**: Requests carrying `X-Idempotency-Key` are cached in DynamoDB with a 24-hour TTL, ensuring repeated deliveries do not trigger duplicate executions.

---

## 5. Secrets Management

- **External Credentials**: API keys, Basic Auth credentials, and Bearer tokens are encrypted at rest using AWS Secrets Manager with AWS KMS Customer Managed Keys (CMK).
- **Frontend Masking**: The frontend API returns only masked representations (e.g. `sk_live_••••••••39ab`). Secret values are never sent over the wire to the web browser.
- **Task Tokens**: Step Functions Task Tokens generated by `.waitForTaskToken` callback states are stored encrypted in the DynamoDB `flowops-main` table and accessed solely by the Approval decision handler.
